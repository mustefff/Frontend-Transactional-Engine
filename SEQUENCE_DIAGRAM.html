Légende des Phases

Phase 0A : Inscription avec OTP (Étapes 1-32)
Interaction AUTH-SERVICE ↔ NOTIFICATION-SERVICE :
1. Client demande un OTP → AUTH-SERVICE génère le code et le stocke dans Redis
2. AUTH-SERVICE publie événement Kafka "otp-requested"
3. NOTIFICATION-SERVICE consomme l'événement et envoie le SMS avec l'OTP
4. Client vérifie l'OTP, complète son profil et définit son PIN
5. AUTH-SERVICE crée l'utilisateur et retourne le JWT token
Phase 0B : Connexion avec PIN (Étapes 1-14)
Le client s'authentifie avec phone + PIN. AUTH-SERVICE vérifie les credentials, génère un JWT token et publie "user-logged-in". HISTORY-SERVICE enregistre la connexion.
Phase 1 : Création du Paiement Marchand (Étapes 1-8)
Le client Flutter envoie une requête de paiement marchand via l'API Gateway. AUTH-SERVICE vérifie le token JWT. MERCHANT-PAYMENT-SERVICE crée le paiement avec le statut PENDING et publie un événement Kafka "merchant-payment-created".
Phase 2 : Traitement de la Transaction (Étapes 9-14)
TRX-ENGINE consomme l'événement, vérifie le solde, effectue le transfert (débit/crédit) et sauvegarde la transaction.
Phase 3 : Historique et Coordination (Étapes 15-18)
History Service (Équipe 3) vérifie le résultat auprès de TRX-ENGINE, enregistre dans l'historique et publie l'événement "transaction-completed".
Phase 4 : Notifications (Étapes 19-22)
Notification Service (Équipe 3) envoie les SMS et emails au client et au marchand.
Phase 5 : Vérification du Statut (Étapes 23-27)
Le client interroge l'API pour obtenir le statut final du paiement marchand (SUCCESS).
Phase 6 : Commande E-commerce (Étapes 1-30)
Flux E-commerce complet :
1. Client crée une commande → ECOM-SERVICE valide et publie "order-created"
2. TRX-ENGINE traite le paiement (débit client, crédit plateforme)
3. HISTORY-SERVICE vérifie et publie "order-paid"
4. ECOM-SERVICE met à jour la commande (PAID → PROCESSING)
5. NOTIFICATION-SERVICE envoie SMS et Email de confirmation
6. Client peut suivre sa commande en temps réel

Points Clés de l'Architecture

✅ AUTH-SERVICE : Gère l'authentification, les tokens JWT, les sessions et la sécurité
✅ MERCHANT-PAYMENT-SERVICE : Gère les paiements marchands, QR Code, Kafka Producer
✅ ECOM-SERVICE : Gère l'e-commerce (produits, commandes, panier), Kafka Producer + Consumer
✅ TRX-ENGINE : Traite TOUTES les transactions (P2P, P2M, E-commerce), Kafka Consumer
✅ History Service : Consumer + Producer (coordinateur)
✅ Notification Service : Consumer (envoie SMS/Email)
✅ Communication asynchrone via Kafka pour le découplage
✅ Toutes les requêtes passent par AUTH-SERVICE pour vérification du token
✅ Équipe 3 gère l'historique et les notifications pour tous
